NPF-Q400 — JOURNAL DES MODIFICATIONS TECHNIQUES

But du fichier
-------------
Ce fichier sert de mémoire technique en cas de perte d'historique de chat.
Il doit rester à la racine du dépôt, à côté de index.html, script.js, style.css, manifest.json et sw.js.

Version actuelle TEST : v12.24
Date de génération : 2026-07-02

Règle de méthode
----------------
- Tester en dépôt TEST avant production.
- Ne jamais modifier l'import offline, le service worker ou IndexedDB en production sans validation TEST.
- Quand une version fonctionne, elle devient la nouvelle base.
- Conserver ce fichier et l'enrichir à chaque version.

v12.15 — Suppression packs + host IGN corrigé
- Modification : suppression robuste des groupes multi-ZIP.
- Modification : moins de confirmations répétées lors de la suppression.
- Modification : IGN_01, IGN_02, IGN_part04 reconnus comme même groupe.
- Modification : host local stable “ign.tile.openstreetmap.org”.
- Pourquoi : les packs installés ne se désinstallaient pas correctement et IGN devait être isolé d'OpenStreet.
- Limite constatée : la première carte importée charge vite, la deuxième devient très lente, quel que soit l'ordre.

v12.16 — Suspension de carte pendant import
- Modification : ajout de suspendOfflineMapRenderingDuringImport().
- Modification : au début d'un import ZIP, le pack offline actif est temporairement désactivé.
- Modification : la couche tuiles Leaflet est retirée pendant l'écriture IndexedDB.
- Modification : le service worker reçoit OFFLINE_ACTIVE_PACKS_CHANGED avec une liste vide.
- Pourquoi : quand une première carte est active, Leaflet et le service worker lisent les tuiles dans IndexedDB pendant que le deuxième import écrit massivement. Sur Safari/iPadOS, cette concurrence lecture/écriture ralentit fortement, voire bloque l'import.
- Effet attendu : le deuxième gros import doit être beaucoup plus rapide.
- Risque : pendant l'import, la carte peut disparaître temporairement. C'est volontaire. À la fin, la carte importée est réactivée et l'application recharge.

Rappel de diagnostic actuel
---------------------------
- IGN importé en premier : fonctionne parfaitement.
- OpenStreet importé en second : devient lent/bloqué.
- Avant, OpenStreet en premier fonctionnait et IGN en second devenait lent.
- Conclusion : ce n'est pas un problème spécifique IGN ou OpenStreet ; c'est un problème de deuxième gros import avec une carte déjà active et une IndexedDB déjà sollicitée.

v12.17 — Troisième import + suppression par blocs
- Constat utilisateur : IGN en premier fonctionne, OpenStreet en second fonctionne avec v12.16, mais OACI installée en troisième rame. La suppression d'IGN n'avance pas non plus.
- Diagnostic : après deux gros imports, IndexedDB est volumineuse. Même si la carte Leaflet est suspendue, le service worker peut garder une connexion IndexedDB ouverte et son cache mémoire. Les suppressions en une grosse transaction donnent aussi l'impression de bloquer car l'interface ne se rafraîchit pas.
- Modification script.js : suspendOfflineMapRenderingDuringImport() envoie maintenant OFFLINE_IMPORT_START au service worker.
- Modification sw.js : réception de OFFLINE_IMPORT_START / OFFLINE_MASS_DELETE_START, vidage du cache mémoire, désactivation temporaire des packs actifs côté SW, fermeture de la connexion IndexedDB du SW.
- Modification script.js : la suppression de pack se fait par blocs de 750 tuiles avec transactions courtes et progression affichée.
- Modification script.js : fallback scan complet si l'index packName ne trouve rien, pour supprimer d'anciens packs mal indexés.
- Modification script.js : les cartes non OpenStreet, dont IGN et OACI, utilisent le mode lecture arraybuffer et des lots plus larges.
- Pourquoi : éviter les conflits lecture/écriture/suppression IndexedDB et rendre visible l'avancement de la suppression.
- Effet attendu : OACI en troisième doit être plus fluide ; suppression IGN doit afficher une progression et finir.

v12.18 — Libération IndexedDB attendue + OACI repassée en blob
- Constat utilisateur : suppression IGN affiche le message mais ne démarre pas ; OACI bloque à “Préparation terminée...” en troisième carte.
- Diagnostic : v12.17 envoyait un postMessage au service worker, mais sans attendre que le service worker ferme réellement sa connexion IndexedDB. L'opération lourde pouvait donc démarrer trop tôt.
- Modification script.js : ajout de releaseOfflineDatabaseForHeavyOperation(), qui suspend la carte, prévient le service worker, ferme la connexion IndexedDB de la page, attend 900 ms, puis rouvre une connexion propre.
- Modification import : OpenStreet reste en profil conservateur ; IGN garde arraybuffer ; OACI revient en blob avec lots plus petits, car l'arraybuffer généralisé pouvait bloquer OACI au début de lecture.
- Modification import : affichage d'un message “Début lecture des tuiles...” puis progression toutes les 10 tuiles pour voir si le blocage est en lecture ZIP ou en écriture IndexedDB.
- Modification suppression : remplacement de la suppression curseur par une suppression getAllKeys + lots de 500 clés ; fallback scan complet si besoin.
- Modification sw.js : OFFLINE_IMPORT_START / OFFLINE_MASS_DELETE_START utilise event.waitUntil(closeOfflineDBForHeavyWrite()) pour fiabiliser la fermeture IndexedDB côté service worker.
- Pourquoi : traiter les deux blocages observés, suppression silencieuse et import OACI bloqué immédiatement après préparation.

v12.19 — Reset complet offline + mode sécurisé OACI
- Constat utilisateur : suppression IGN bloquée sur “Suppression 1/7 : IGN-01...” ; import OACI bloque/crashe à “Lecture tuiles 51/3347”.
- Diagnostic suppression : la base IndexedDB est probablement verrouillée ou trop fragmentée pour une suppression pack par pack fiable après plusieurs gros imports.
- Modification UI : ajout d'un bouton “Tout réinitialiser” dans la gestion des cartes offline. Il supprime toute la base OfflineTilesDB et tous les packs offline, puis recharge l'application.
- Pourquoi : fournir une méthode de réparation fiable quand les suppressions pack par pack ne démarrent pas.
- Diagnostic OACI : OACI plantait très tôt en troisième import, probablement par pression mémoire/IndexedDB après IGN + OpenStreet.
- Modification import OACI : mode sécurisé avec lots de 10 tuiles, réouverture IndexedDB toutes les 200 tuiles, lecture blob, progression toutes les 10 tuiles.
- Modification import OACI : si une tuile échoue deux fois à la lecture, elle est ignorée au lieu de faire planter tout l'import.
- Risque : OACI peut être un peu plus lente, mais doit cesser de planter à 51/3347.
- Recommandation : si la base actuelle est déjà bloquée, utiliser d'abord “Tout réinitialiser”, puis réinstaller les cartes.

v12.20 — Nouvelle base IndexedDB offline
- Constat utilisateur : reset complet bloqué vers la moitié avec “Suppression bloquée”.
- Diagnostic : indexedDB.deleteDatabase('OfflineTilesDB') reste bloqué si Safari/iPadOS ou l'ancien service worker garde une connexion ouverte. Tant que cette connexion existe, la suppression complète ne peut pas aboutir.
- Décision : ne plus dépendre de la suppression de l'ancienne base. La v12.20 abandonne l'ancienne base OfflineTilesDB et utilise une nouvelle base OfflineTilesDB_v12_20 côté script.js et sw.js.
- Modification script.js : ajout de OFFLINE_DB_NAME = 'OfflineTilesDB_v12_20' et ouverture IndexedDB via cette constante.
- Modification sw.js : DB_NAME = 'OfflineTilesDB_v12_20'.
- Modification reset : le bouton “Tout réinitialiser” devient un reset logique. Il vide les listes locales, désactive les packs actifs, nettoie les caches de tuiles, crée/ouvre la nouvelle base et recharge. L'ancienne base est seulement supprimée en tentative non bloquante.
- Pourquoi : retrouver une application utilisable même si l'ancienne base est verrouillée.
- Limite : les anciennes tuiles peuvent rester dans les données Safari du site et consommer de l'espace. Si le quota iPad devient insuffisant, il faudra supprimer les données du site NPF-Q400 dans Réglages Safari.
- Test conseillé : installer v12.20, faire MAJ, fermer/réouvrir, cliquer “Tout réinitialiser”, puis réimporter OpenStreet, IGN et OACI.

v12.21 — Version de récupération service worker
- Constat utilisateur : après installation v12.20, la carte ne charge pas ; les icônes sont visibles mais les boutons ne fonctionnent pas.
- Diagnostic : très probablement mélange de fichiers ou ancien service worker encore actif après les essais de suppression IndexedDB. Le HTML/CSS s'affiche mais le JavaScript applicatif ne s'initialise pas correctement.
- Modification index.html : ajout d'une séquence de récupération exécutée une seule fois en v12.21. Elle désenregistre les anciens service workers, supprime les caches app-shell NPF-Q400, puis recharge une URL fraîche.
- Modification script.js/sw.js : nouvelle base IndexedDB OfflineTilesDB_v12_21 pour éviter toute base verrouillée précédente.
- Pourquoi : repartir sur un couple index/script/sw cohérent et éviter les anciens caches après blocage.
- Test conseillé : remplacer les fichiers, ouvrir avec connexion, laisser l'application recharger automatiquement une fois, puis cliquer MAJ et fermer/réouvrir.

v12.22 — Stabilisation offline, reprise iPad, chat
- Constat utilisateur : suppression OpenStreet trop lente/inutilisable ; message “importation en cours” puis suppression extrêmement lente ; OACI redevient lent après nettoyage ; reprise iPad après veille un peu lente ; besoin d'un bouton chat Reconnecter et d'une fermeture plus visible.
- Modification script.js : remise à zéro de isZipImportRunning au chargement pour éviter qu'un import interrompu bloque les actions suivantes.
- Modification script.js : OpenStreet passe en suppression logique. L'application retire le groupe OpenStreet de la liste et le désactive sans parcourir physiquement 1 Go de tuiles IndexedDB.
- Pourquoi : la suppression physique d'OpenStreet est trop lourde et instable sur iPad/Safari ; “Vider le cache” reste la méthode de nettoyage lourd.
- Modification import OACI : lots augmentés de 10 à 35 et réouverture IndexedDB toutes les 350 tuiles pour accélérer sans revenir au mode trop agressif qui plantait.
- Modification reprise veille : plusieurs invalidateSize/redraw espacés après focus/pageshow/visibilitychange.
- Modification chat : ajout d'un bouton “↻ Reconnecter” pour forcer la reconnexion après changement de pseudo ou de canal.
- Modification chat : bouton de fermeture rendu rouge et plus visible.
- Non inclus volontairement : Base OACI saisissable, multi-vols Bloc/Fuel, et déroutement “vide retardant”. Ces fonctions seront traitées ensuite par versions séparées pour éviter les régressions.

v12.23 — Chat auto-reconnect + fermeture plus propre
- Constat utilisateur : le bouton fermeture chat de v12.22 n'est pas esthétique ; le bouton Reconnecter fonctionne mais il serait préférable de reconnecter automatiquement quand le canal ou le pseudo change.
- Modification script.js : le bouton de fermeture chat affiche désormais “✕ Fermer” au lieu d'un symbole moins + ajout CSS.
- Modification script.js : ajout d'une reconnexion automatique après modification du canal ou du pseudo, avec temporisation 1,2 s pour éviter une reconnexion à chaque lettre.
- Modification script.js : si le chat n'est pas connecté, la modification canal/pseudo est simplement mémorisée ; si le chat est connecté ou en connexion, l'app déconnecte puis reconnecte automatiquement.
- Modification style.css : fermeture en bouton pilule blanc/rouge plus propre, suppression du pseudo-texte CSS précédent.
- Non modifié : import OpenStreet. Le mode OpenStreet reste volontairement conservateur car c'est le pack de 1 Go le plus risqué pour Safari/iPadOS. À réévaluer après un test complet de durée.

v12.24 — Chat Valider + OpenStreet découpé plus rapide
- Constat utilisateur : l'auto-reconnexion chat n'est pas souhaitée ; il faut un bouton “Valider” qui se dégrise quand canal/pseudo change. OpenStreet était rapide quelques versions avant ; les ZIP actuels ne sont pas volumineux mais l'import est redevenu très long.
- Modification chat : suppression de la reconnexion automatique à chaque changement stabilisé.
- Modification chat : ajout d'un bouton “Valider”, grisé par défaut, qui se dégrise uniquement quand le canal ou le pseudo diffère de la configuration validée.
- Modification chat : au clic Valider, la configuration est mémorisée et le chat se déconnecte/reconnecte si nécessaire.
- Modification OpenStreet : pour les ZIP OpenStreet non volumineux (<300 Mo), on évite la libération lourde IndexedDB avec attente de 900 ms avant import.
- Modification OpenStreet : lots d'écriture non-gros OpenStreet portés à 260 tuiles pour revenir vers un profil plus rapide.
- Pourquoi : les ZIP OpenStreet découpés ne doivent pas subir le profil très conservateur prévu pour un gros ZIP unique d'environ 1 Go.
